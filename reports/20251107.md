#### Where I Had Trouble
- Could not find a reliable way to execute code in browser which was what we were planning for demo

    - The constant internal error message and wall time out message when I tried forcing cgroup v2 to work
    - On my host machine I am running I tried editing GRUB boot config after reading Arch wiki to force v1 but it behaved in unexpected ways
    - I tried Docker-in-Docker (Ubuntu container to wrap Judge0 container with a shell script to try to force v1 but realized containers share host kernel and so this idea of mine was dumb)
    - Got Judge0 working on a Ubuntu 22.04 (recommended distro) VM after I did the recommended cgroup downgrade on it (but I did not want my peers to have to setup a VM just to test our product)

- Piston was actually way better as its a smaller image (~1GB) and had cgroup v2 support (worked on my machine without VM), BUT:
    - Judge0 can run standalone as a code execution worker, or as multiple worker containers paired up with a Judge0 "manager" connected to a Postgres/Redis DB/cache for a queueing system out of the box; Piston does not have this and we will need our implementation (I think)
- Debugging was annoying at times because I would know the code solutions I submit through editor were right but no proper console emulation meant I had no idea where along the way it would break for the tests to have failed
