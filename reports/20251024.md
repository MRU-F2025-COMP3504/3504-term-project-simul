#### What I Learned

My dependency management solution does not play super well with NPM. I use Nix
to manage all my programming dependencies (NPM / Node versions, docker versions,
etc), and I use NPM to manage the packages within the project. For the most
part, this is sick, as it guarantees absolute reproducibility in every
environment! For instance, we install Nix on our CI machines so that our testing
environment is identical to our (my) development environments.

However, Nix doesn't allow for arbitrary execution of dynamically linked
executables: in this case, these executables were the browser environments used
during testing. This means I had to install the browser executables via Nix,
instead of NPM. This opened a whole can of worms, as Nix's documentation is
infamously atrocious, and didn't specify what versions of the browsers it was
installing. This lead to me manually testing every version of the Playwright NPM
package to find the one the Nix flake was using under the hood.

The good news is that we're now guaranteed that these browsers will work! Our CI
uses browsers that were built from source in isolation, meaning we're not prone
to any version-by-version errors or NPM supply-chain attacks. The bad news: this
took me three hours.
